when you have a certain chore that you need to do repeatedly with a certain input and output, especially when it involves multiple steps or easy but boring not straightforward, you probably need to give the ai a context once so you dont have to repeatedly tell it to delegate your chore to it. that's where skill and subagent comes in handy.

at first, i dont really know the difference between the two because basically they are a context in the form of markdown file. you describe the task, explain the steps to finish it, set rules it should follow etc. now, the differences that i know of are:
- subagent has its own context window, separated from the main chat session. the main session only consumes token generated by the subagent result. the tokens used by the subagent during its thinking or execution phase only resides in its own context window. on the other hand, skill doesn't have its own context window. everything is in the main session
- we can continue the main session without having to wait for the subagent to finish. the main agent will then automatically respond when the subagent finishes. well, similar to calling an async function basically. skill however, if we want to continue chatting with the agent, we should either wait for the agent to finish the skill or create another session
- use /{skill-name} to explicitly run a skill. there is no special way to run a subagent. it's either automatically called by the main agent based on our prompt or we explicitly tell the main agent to summon the subagent
- we can limit the tools exposed and model used to the subagent whereas skill, i'm not sure (the blog content auditor agent should clarify and update this part both here and in the final draft)

in this website's repo i also implement some subagents and skills. well there is no specific reason why a subagent has to be a subagent and a skill has to be a skill. in my case here, i can convert a skill to a subagent and vice versa

for subagents, i have content auditor and writer for both blog and project. so there are 4 subagents in total. the auditor agent takes my original writing which i push to the [repo](../), check it against some writing rules, and report it back to the main agent so the context can be forwarded to the writer agent who then basically paraphrase my original writing. i separate the subagent between the blog and project because i want the project content to explain itself using STAR (situation, task, action, result) framework. while for the blog, SEO is the main concern. the auditor can be used against a finished content though for improvement purpose though.

for skill, the one i want to highlight is the blog cover generator. until recently, i do all the process manually from:
- looking for the perfect background in Unsplash
- running a local dev server of an Astro page showcasing a background and a text
- changing the background to the image i download from Unsplash, changing the text to a blog title i want to give a cover for
- taking a screenshot, auto saved as png
- converting it to a webp file using an online tool
- setting the cover in the blog's frontmatter using that webp image
the skill, which you can check in [here](../../skills/blog-cover/SKILL.md) now does that for me except for looking for background in Unsplash because i want it to be as deterministic as possible. i trust my taste better.

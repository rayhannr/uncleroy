there was a reorg in my company last month. my manager told me that i was assigned to improve an admin dashboard which has been around for around 8 years and which i have contributed the most for the last 5 years out of other products. the assignment was probably because i'm the subject matter expert. 

honestly, it concerned me at first. as the company moves towards ai-first direction, the focus of course will be cli, mcp, ai plugins. all the things that allow users to interact with our product through their ai agents. i felt like the dashboard would matter less over time, and i'd be spending my days polishing a product that's potentially heading towards deprecation.

but then i raised this concern to my manager and the conversation after that shed lights of hope, kind of. we agreed that the dashboard is not going anywhere despite no longer becoming the product users will interact with the most. cli, mcp, and ai plugins are not one-size-fit-all. well they are definitely good, it could help us set things up without having to navigate around menus in the dashboard. however, not every use case would be easier with them. even if it would, not every user would prefer them to dashboard

i'll take my own experience as an example. i use supabase for my personal projects that require db. back then when ai-assisted coding wasn't a thing and sql script wasn't really my thing, i created the tables in supabase dashboard. it was pathetic and took a lot of time. now at first i usually discuss about the core idea of the app i want to build and what tables i will need for that app with an ai agent. the agent will then generate a migration script which i could just run with cli. if i want to pull migration from prod to local, i also use cli. however, for straightforward stuff like checking on whether my user data is created after signing up, enabling third party login, or adding a single optional column in a table when the app is still not in production, the dashboard is still my way to go because it is much simpler to just go there rather than writing some cli comamnd or prompt to an ai agent.

same thing for vercel. it has cli, but i still use its dashboard to check my failed deployments, analytics of this blog, results of cron jobs, and even setting up env var of some projects. with vercel, i don't remember one time when i need to do multi-step operations which require me to navigate to many menus in the dashboard. all i do just a simple CRUD with minimum steps. so dashboard makes more sense to me in this case because i don't have to memorize the cli commands or asking ai about the command, hence more time saved.

another example is the admin portal i talk about earlier. basically it's a portal for game admin (publisher, studio, or individual) to setup the backend of their game. they can look into user profile, ban users, create a leaderboard config, update a price of an item they sell in their game store, configure third party login, check their billing for this month and many more. 

from my perspective as a user, the dashboard is easier when it comes to simple one time operation such as banning user, checking this month's billing, or disabling login with google. i don't have to navigate to many menus and i already get what i want. besides, the interface is much more pleasing to see than just json. however, for complex task such as creating a proper matchmaking which requires navigating to multiple menus and setting up many fields, cli is definitely my go to. with the help of the ai plugin or mcp, i could just ask write a prompt to an ai agent and it'll call the cli or the mcp tools to set everything up for me.

last example is my own project, [places to go](../../../src/contents/project/places-to-go.md). initially i manually updated my google spreadsheet every time i found an interesting restaurant, mostly from instagram. the flow is find a good place on instagram > check the place in gmaps and copy the link > write down the name and city + paste the link to the spreadsheet. it is tiring because i have to jump around 3 apps. this is where mcp came in handy. i setup an mcp with tools like get place by name/category/city, add a place including distance and travel time from my house, find nearest places from my live location, and many more. so now i can just paste the link to my claude app connected to the places to go's mcp, it'll add the place to the sheet for me. i barely touch the spreadsheet anymore. the last time i did was to add a new category column. it was painful because i gotta do it manually for 200+ rows as i don't want to give it to an ai agent to just add random and inaccurate category to the places.

so my key takeaway is that dashboard, cli, mcp, or whatever that is has their own use cases and each use case can have different kind of users. for me personally, cli is very helpful when i need to do many things to get one thing right. and for simple task that can be done in one step, dashboard is much more easier as no command to memorize or prompt to write. all i need is just a few clicks. there must be people who have different view from mine. so, a winning product is the one who can support more people with distinct opinions and preferences.
